# EDA Findings — rfm-analysis-of-bank-clients (bank transaction log + RFM output)

**Дата:** 2026-10-13
**Полный отчёт:** `reports/eda/eda-rfm-bank-2026-10-13.md`
**Slug:** `rfm-bank`

## Датасет вкратце

`data/bank_rfm_dataset_10k_fixed.csv` содержит **10 000 строк**, одна строка = **одна транзакция**
(`customer_id × transaction_date`), плюс производная `data/rfm_output.csv` — **1 983 строки**,
одна строка = **клиент** (RFM-сегмент). Период: **2023-01-01 → 2024-03-30** (15 месяцев).
Качество данных в целом **хорошее по форме** (0 пропусков, 0 дубликатов, валидные диапазоны),
но с одной структурной особенностью: `is_anomaly` — фактически порог по `amount`, а не
независимая метка аномалии.

## Топ проблем качества

### Проблема 1: `is_anomaly` механически связан с `amount` (P1)
- **Что:** r(`amount`, `is_anomaly`) = **0.90**; все 508 аномалий имеют `amount` ≥ 15 209, ни одна
  чистая транзакция не превышает 26 731. IQR-выбросы ловят все аномалии (recall 1.00), но с
  precision 0.65; z-score — precision 1.00, recall 0.65. Средний чек аномалии ×20 к чистым.
- **Влияние:** «очистка аномалий» — это обрезка верхнего хвоста распределения, а не удаление шума.
  Все downstream метрики (Gini, топ-сегменты, тренд) считаются на усечённом сверху frame.
- **Действие:** назвать флаг amount-driven в README/data dictionary; описать эффект drop; для
  отчётности по выручке рассмотреть winsorize вместо полного drop.
- **Владелец:** аналитик / автор генератора данных.

### Проблема 2: README headline описывает post-filter срез, не сырой файл (P2)
- **Что:** «1 983 clients on 9 492 transactions» (README.md:3,50) верно только для frame после
  `is_anomaly==0`. В сыром файле — **10 000 транзакций и 1 985 клиентов**; 2 клиента
  (`user_1881`, `user_417`) существуют только через аномальные транзакции и исчезают после фильтра.
- **Влияние:** читатель не понимает, что headline — про очищенный срез; цифры «сырого» лога на 5% больше.
- **Действие:** в README указать явно «после удаления 508 аномальных транзакций»; в data dictionary
  зафиксировать оба числа.
- **Владелец:** автор README.

### Проблема 3: циклическая валидация сегментации (P2)
- **Что:** сегменты определены через `M_Quartile` (r = 0.91 с `monetary_value`), и затем тот же
  `monetary_value` используется как доказательство бизнес-смысла (Gini, concentration ratio).
- **Влияние:** разрыв ×3.14 Champions/Hibernating частично заложен в определении; вывод «сегментация
  имеет смысл» опирается на метрику, из которой она построена.
- **Действие:** пересобрать сегменты без `M` в определении (только R и F) и проверить, сохраняется
  ли разрыв по `monetary_value`.
- **Владелец:** аналитик.

### Проблема 4: вся волатильность сырого тренда — артефакт невыброшенных аномалий (P2)
- **Что:** сырой недельный ряд даёт много недель ±30–365%; в неделю 2024-03-03 10 аномалий дают
  ~756k из 1 126 870 выручки (~67%). На очищенном frame — только рамп-ап и одна поведенческая неделя.
- **Влияние:** профилировщик (работает на сыром файле) сигналит ложные инциденты динамики.
- **Действие:** профилировать очищенный frame для трендовых проверок; документировать разницу.
- **Владелец:** аналитик.

### Проблема 5: транзакционные срезы не дают сигнала (P3)
- **Что:** gap медианы `amount` по `product_category` = **×1.11**, по `payment_method` = **×1.08** —
  ниже порога 1.5. Размер чека не различает ни категорию, ни канал.
- **Влияние:** таргетинг по категории/каналу бесполезен; ценность живёт на клиентском уровне.
- **Действие:** не строить кампании на транзакционных срезах; использовать RFM-сегменты.
- **Владелец:** маркетинг / аналитик.

## Что в порядке

- 0 пропусков во всех колонках обеих таблиц.
- 0 полных дубликатов строк и 0 дубликатов по ключу `customer_id × transaction_date` — grain чистый.
- `amount` ≥ 0 (min 500.27), `transaction_date` без будущих дат (max 2024-03-30), категории и каналы
  без мусорных значений.
- Агрегат `monetary_value` сходится с суммой `amount` по клиентам: 28 673 283.56.
- README-таблица результатов воспроизводится из `data/rfm_output.csv` (см. `tests/test_readme_numbers.py`).
- **Все 5 headline-чисел README — REPRODUCED** (1 983 clients, 9 492 transactions, Gini 0.324,
  top-20% 38.2%, mean RFM 7.50).
