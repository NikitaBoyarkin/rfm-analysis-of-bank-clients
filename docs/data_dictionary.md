# Data dictionary

Catalog of fields in the source dataset and the derived RFM table.
Use this to write SQL/analysis queries against the project without re-reading the code.

## Source: `data/bank_rfm_dataset_10k_fixed.csv`

Synthetic transaction log. Generated by `generate_data.py` (seed 42), 10 000 rows, ~2 000 customers, period 2023-01-01 → 2024-04-01.

| Field | Type | Description | Domain |
|---|---|---|---|
| `customer_id` | string | Customer identifier | `user_1` … `user_2000` |
| `transaction_date` | datetime | Transaction timestamp | 2023-01-01 09:00 → 2024-04-01 |
| `amount` | float | Transaction amount, RUB | ~500 … 100 000 (5% anomalies) |
| `product_category` | string | Banking product | Кредит, Дебетовая карта, Вклад, Страхование, Инвестиции, Ипотека |
| `payment_method` | string | Payment channel | карта, Apple Pay, Google Pay, криптовалюта, банковский перевод |
| `is_anomaly` | int (0/1) | Flagged anomalous transaction | 0 = normal, 1 = anomaly (~5%) |

**Notes**
- `is_anomaly == 1` rows are dropped before RFM aggregation (see `drop_anomalies`).
- Amount distribution: 95% exponential(scale=2500)+500, 5% uniform(15000, 100000).
- Product probabilities: 0.30 / 0.25 / 0.15 / 0.10 / 0.10 / 0.10.

## Derived: `data/rfm_output.csv`

One row per active customer (after anomaly drop, ~1 981 rows).

| Field | Type | Description | Range |
|---|---|---|---|
| `customer_id` | string | Customer identifier | — |
| `recency` | int | Days since last txn vs snapshot (max txn date + 1 day) | 0 … ~455 |
| `frequency` | int | Number of transactions | ≥ 1 |
| `monetary_value` | float | Sum of `amount` | > 0 |
| `R_Quartile` | int | Recency quartile, **higher = more recent** | 1..4 |
| `F_Quartile` | int | Frequency quartile, higher = more frequent | 1..4 |
| `M_Quartile` | int | Monetary quartile, higher = more spend | 1..4 |
| `RFMClass` | string | 3-digit combo `R F M` | "111" … "444" |
| `RFMScore` | int | Sum of quartiles | 3..12 |
| `Segment` | string | Named segment (combo-based) | Champions, Loyal, Potential Loyalists, At Risk, Need Attention, Hibernating |

## Segmentation rules

Combo-based (not sum-based) — preserves which dimension drives the label.

| Condition | Segment |
|---|---|
| R ≥ 4 & F ≥ 4 & M ≥ 4 | Champions |
| R ≥ 3 & F ≥ 3 & M ≥ 3 | Loyal |
| R ≥ 3 & M ≥ 3 | Potential Loyalists |
| R ≤ 2 & F ≥ 3 | At Risk |
| R ≤ 2 & F ≤ 2 | Hibernating |
| else | Need Attention |
